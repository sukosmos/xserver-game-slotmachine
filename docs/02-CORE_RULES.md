## 2.2 가중치
`P(symbol=s) = modifiedWeight[s] / sum(allModifiedWeights)`.
- 등장 가중치 증가 아이템은 확률 **퍼센트포인트 추가가 아니라 가중치 정수 추가**.
- 예: `cherry +10` 보유 시 체리 확률 `40/110 ≈ 36.36%`.
- 중첩 시 모든 가중치를 합한 뒤 정규화. 가중치 0/음수는 허용하지 않는다.
- 조건 없는 기본 결과는 PRNG가 선택한 9개 심벌로 확정. 슬롯 애니메이션은 추첨 결과를 표현만 함.

## 2.3 당첨과 점수
1. **심벌 기본 점수(baseScore):** 최종 보드 9칸의 개별 점수 합산. 조커 와일드는 중앙 칸의 원래 심벌 개별 점수를 사용.
2. **라인 배당(lineScore):** 완성된 각 라인에 대해 심벌의 3일치 기본 배당 지급. 서로 겹치는 라인도 각각 독립 지급.
3. **전용 배당 아이템:** 같은 심벌 전용 아이템은 합연산 방식, `factor = 1 + sum((item.effect.extraFactor.num / item.effect.extraFactor.den) × copies)`; 각 라인마다 `floor(basePayout × factor × perLineSpecialFactors)`.
4. **전역 배율:** `floor((baseScore + sum(lineScores) + virtualLineBonuses) × product(globalMultipliers))`.
5. 최종 점수는 음수가 될 수 없다. 일단 세부 정수 내림 지점은 단계 3과 4의 위 규정으로 통일.

예: 체리 라인 1개, `황금 수확` 1개 => `floor(30 × (1+2)) = 90` 라인 점수.

- Wild(중앙만 적용): 해당 라인을 평가할 때 다른 2칸이 동일 심벌이면 그 심벌로 계산. 다른 2칸이 다르면 불일치. 중앙 Wild는 중앙 칸의 표면 심벌을 바꾸지 않음.
- 전역 배율을 적용할 때 `악마의 계약`처럼 baseScore를 0으로 만드는 조정은 **전역 곱셈 이전**에 처리.
- 동점/배율 처리에 JS float를 사용하지 않도록 정수/유리수 연산 권장.

## 2.4 Hand와 라운드
- **기본 4 Hand/라운드 (MVP 가정)**. 비교 실험으로 3 Hand 예정.
- 1 Spin = 1 Hand 소모, 베팅칩 없음.
- 라운드 진입 시 `roundScore=0`, `handsRemaining=4`(아이템 변형 전).
- 목표 달성 시 **정산(Stop & Collect)** 버튼 활성화. 남은 Hand를 버리고 코인 보너스로 전환할 수 있음.
- 목표 미달이면 정산 불가. Hand 0에 목표 미달이면 즉시 런 실패.
- 목표 달성 후 남은 Hand 모두 소비해도 라운드 성공. 추가 점수는 런 누적 점수에 반영.
- 성공 시 점수는 다음 라운드로 이월하지 않고, `runTotalScore`에만 합산. `runTotalScore`는 실제 발생한 모든 Hand 점수의 합.
- 아이템의 `next N spins` 기한은 베팅액이 아니라 실제 Spin 횟수에 따라 감소.

## 2.6 난이도 검증 메모
기본 4 Hand, 아이템 없음, 8라인, 5심벌 독립 추첨의 단순 Monte Carlo(2026-10-25 계산)에서 첫 라운드 목표 **120점** 통과율은 대략 **90%**. 반면 옛 초안 목표 200점은 대략 **49%**로 지나치게 어려워 120점으로 수정. 이는 실제 밸런스 보장이 아닌 난수 시뮬레이션 추정이므로 테스트를 재실행할 것.

Phase 0~1 실제 엔진의 고정 시드 100,000라운드 재검증 결과는 **90.671%**였다. 실행법은 `npm run test:balance`, 표본/관측 분포/한계는 `09-TEST_CASES.md` 9.6을 참고한다.
