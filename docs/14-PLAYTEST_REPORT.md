# 14. Phase 5 플레이테스트 보고서

2026-10-26 · Node.js 22.23.2. 아래 Phase 5 표는 v0.6의 역사적 결과다. 최신 v0.7 결과는 마지막 항목을 참고한다.

## 재현 방법

```sh
npm run check
npm run simulate:runs -- 10000 docs/v0.7-simulation.json
```

원자료는 [phase5-simulation.json](phase5-simulation.json)이다. 공개 테스트 시드 `nine-phase5-v1`에서 런 번호별 SHA-256 시드를 만들고 실제 서버 도메인 엔진과 난수 스트림으로 진행했다. 운영 런의 비밀 시드는 사용하지 않는다.

정책은 목표 달성 즉시 정산하고, 살 수 있는 상품 중 비경제 아이템 → 낮은 가격 → ID 순서로 구매한다. 더 살 수 없으면 무료 리롤을 사용하거나 최저 기본 가격을 남길 수 있는 경우 상점당 유료 리롤을 최대 1회 사용한다. 폐기는 하지 않는다. 이 정책은 재현 가능한 기준선이며 최적 전략이 아니다.

저가 상품을 먼저 사는 정책 때문에 저가 가중치/배당 아이템에 표본이 집중된다. 활성 라운드 집계는 해당 라운드 시작 시 보유한 아이템을 기준으로 하며, 중간에 만료돼도 그 라운드에 포함한다. 이 수치는 아이템별 인과적 파워 순위가 아니다. 고가 경제 아이템·희귀 조작 아이템과 후반 빌드의 표본이 부족하다.

후속 튜닝 후보는 2~4라운드 목표 상승폭과 초반 구매력이다. 숫자를 바꾸기 전 저축/경제 우선/동일 심벌 시너지 정책을 같은 조건으로 비교하고, 아이템 단독 효과는 고정 시작 빌드의 대조 실험으로 분리해야 한다. 이번 단계는 측정과 문제 식별까지 완료했으며 밸런스 변경은 후속 작업으로 남긴다.

## 브라우저 인수

실제 로컬 화면과 HTTP/SQLite를 연결하고 다음 경로를 직접 조작해 확인했다. 브라우저 조작은 수동 인수이며 아래 자동 테스트와 구분한다.

- 실제 v0.6: 새 런, 스핀/당첨 라인, 목표 달성, 정산, 상점의 가격·구매 가능/코인 부족 표시.
- 테스트 규칙: 아이템 구매/품절, 리롤 비용 증가, 다음 라운드 활성화, 조커의 가면 2→1 Hand, 새로고침 후 보드·점수·아이템 복구.
- 10라운드 승리와 4 Hand 실패를 각각 브라우저에서 진행한 뒤 랭킹의 완료 라운드/정확한 점수 반영을 확인했다.
- 360px 폭의 슬롯·도감 배치에서 가로 넘침이 없고 점수/Hand/코인/구매 가능 여부를 표시한다. 데스크톱 1280px 배치도 확인했다.

승리/실패 인수는 `node scripts/preview-fixtures.js`로 재현한다. 3001은 목표 1, 3002는 큰 목표와 3종 상품 풀을 사용하는 메모리 전용 서버다. 초기 Phase 5 인수는 시작50코인으로 수행했고 v0.8에서는 JSON 시작3코인을 따른다. loopback에만 열리며 실제 `.runtime`이나 JSON 파일을 수정하지 않는다. 작업 후 Ctrl+C로 종료한다. 인수용 낮은 목표의 승리를 실제 밸런스 완주 기록으로 해석하지 않는다.

## 자동 테스트
Phase 5 화면 정리와 심벌 강화 표 보완 당시 테스트는 **199개 통과**였다. 당시 점수 계산 함수 공유 후에도 10,000런 원자료와 전체 결과가 동일했다. 현재 브라우저 테스트의 상품 풀은 체리 농장·황금 수확·조커의 가면이다.


초기 Phase 5 검증: `npm run check` 191개 통과. 문서·JSON 검사 외에 정적 파일 허용 목록/CSP, 로컬 연결 Origin/Host 보호, 소유자별 카탈로그와 과거 규칙 고정, 연결 실패 후 동일 키 재시도, 새로고침/계정 전환, 매우 큰 점수 표시, 전체 런 재현성과 라운드 경계를 검증한다. 기존 API·경제·암호화 저장·재시작·동시성·랭킹 테스트도 통과했다.
